## Key decisions & rationale

- **#6 predicate = `World.BelongsTo`** (not land-owner): keeps CombatStrength on the same ownership notion as logistics/AI consumers; `TerritoryRules = true` in the test worlds mirrors production (`OriginalScenario.cs:99`). Reviewer confirmed all other `Piles` consumers already use `BelongsTo` - no sibling fix needed.
- **#10 = new `Draw.OwnAiCharacter` (value 4) + static `GameSetup.RandomFor(seed, draw)`**: appending keeps enum values 0-3 stable so no existing seeded stream shifts (guard-tested + DeterminismTests); the client creates the seeded Random per `NewAi` call (the field initializer runs before any world exists; `random` is consumed only for the character draw, so per-call creation is deterministic across key-I toggles - intended per plan decision).
- **#11 ladder clamps instead of breaks**: hex distance reaches `2*(size-1)`, so `radius > map.Size` does not mean "no field can be that far" (the plan's original premise, corrected by review F-WATCHDOG-1); every rung is clamped (`Math.Min`), `lastTried` dedups, comment reworded as a cost cap.
- **#11 diagnostic = `GameEvents` `settlerWalledIn`** (not console/Problems): the established observable-and-assertable surface; data + de/en/pl texts ship in the same commit (`Raise` no-ops silently on unknown ids).
- **OBS-2R guard = `CanLeave` (6-neighbor `PathFinder.AreConnected`), not `World.Reachable`**: specialists are `RoamsFreely`, an own-land-based check would over-reject mobile carriers on neutral terrain; semantics follow the `settlerWalledIn` concept. Reviewer verified the judgment sound. Deferred-conversion drain re-checks it too (`c0ddd52`) so the XML-doc contract "walled-in ones stay carriers" holds on all paths.
- **Declined-with-reason**: 60-s event cooldown can swallow a second same-player walled-in event - kept, matching the established `attacked`/`donkeyRobbed` spam-prevention pattern (reviewer: by-design).
- **Exit sweep equivalence**: single-suite repo - `dotnet test` runs the full tree regardless of diff scope, so the `c0ddd52` sweep already satisfied "full sweep at final HEAD"; re-running the identical command was skipped per run-each-check-once (state normalized with `last_sweep_kind: full`).

# Client UI: typed UiLayout loader for ui.json + name the panel-menu protocol (IPanelMenu, shared helpers)

> Source: plan-orchestrator 2026-11-05. Approach: sequential phases (test bed → UiLayout + meta-test → shared helpers/PanelLayout → IPanelMenu + menu migration → screens migration → rider → full gate); per-menu tasks inside phases are mechanical and partly parallelizable across disjoint files. Tier: full.

## Goals

1. One typed `UiLayout` (pure-data records mirroring `data/ui.json`) loaded **once** in `MapGame.LoadContent` and passed to constructors — no constructor parses `ui.json` itself.
2. `LanguageTests`-style meta-test (in a new `Homestead.Client.Tests` project): every key `UiLayout` reads exists in `data/ui.json`, and every non-comment top-level key of `ui.json` is read (bidirectional drift gate).
3. `interface IPanelMenu` names the existing Draw/Update/Hover triple; the 8 panel sub-menus implement it; `MapGame`'s per-menu if/else dispatch collapses to uniform interface calls.
4. `Frame` (5 copy-pastes), hover-overlay, `Heading`, spinner-half move into one shared static helper class beside `ShareBar`/`Charts`.
5. `BuildMenu.Content`/`TabBar` statics replaced by a `PanelLayout` passed to menus.
6. Rider (F-MIN-1): `CampaignConfig.Load()` statically cached; `Lang.SaveName` no longer re-reads `campaign.json` per list-entry draw.
7. Pure hit-test/layout helpers tested in `Homestead.Client.Tests`; `scripts/fast-checks.sh` passes.

## Context

## Decisions & Rationale

- **`UiLayout` is pure data, textures stay where they are** - alternatives: UiLayout holding `Texture2D` (rejected: needs `GraphicsDevice`, per-people recreation lifecycle in `UsePeople` `MapGame.cs:793-829`, untestable); leaving texture conversion per menu (kept: menus already own `device`/`gfx` and their `IDisposable` textures). Tradeoff accepted: records carry GUI indices/rects/ids; each consumer still does `gfx.Open(file).ReadGui(index)` → `Texture2D`. Basis: code-internal `ManufactureMenu.cs:36-40`, `TransportMenu.cs:42-49`.
- **Records nested inside `UiLayout`** (e.g. `UiLayout.TextButtonSkin`, `UiLayout.PanelTabs`) - alternatives: top-level records `PanelTabs`/`GoodsGrid`/`Portraits` (rejected: name collisions with the existing classes `PanelTabs.cs`, `GoodsGrid.cs`, `Portraits.cs`). Basis: code-internal.
- **Meta-test is bidirectional** (all read keys exist AND all non-`_` top-level keys are read) - alternatives: one-directional (rejected: widget-geometry schema drift — a key nobody reads — stays invisible, exactly the F-UI-1 finding). Mechanism: `UiLayout` reads only through a small internal reader that records each JSON path it resolves; the test loads `UiLayout` from the repo's `data/ui.json` (load itself throws on a missing required key) and asserts recorded top-level keys == the file's non-`_` top-level keys. Basis: issue AC "every key UiLayout reads exists" + `LanguageTests` precedent `tests/Homestead.Simulation.Tests/LanguageTests.cs:59-70, 106-112`.
- **New test project `tests/Homestead.Client.Tests`** (xunit, CPM, `ProjectReference` to `Homestead.Client`) - alternatives: putting tests in `Homestead.Simulation.Tests` (rejected: its csproj references Simulation/Assets/Server only — `Homestead.Simulation.Tests.csproj:18-22` — adding the Client exe there widens an unrelated suite; the issue names `Homestead.Client.Tests`). `data/` lands in the test bin transitively via `Homestead.Simulation.csproj:9` (`None Include="../../data/**/*.json" CopyToOutputDirectory`), so `BuildingCatalog.DefaultDataDirectory` (`BuildingDefinition.cs:111`, `AppContext.BaseDirectory/data`) resolves like in `LanguageTests`. MonoGame `Rectangle`/`Vector2` are pure structs — no `Game`/`GraphicsDevice` needed for the pure-helper tests. Basis: code-internal + CLAUDE.md test conventions.
- **Canonical `IPanelMenu` triple**: `void Draw(SpriteBatch, Texture2D, UiFont, World, int, Vector2, float seconds)` · `string? Update(Vector2, bool pressed, bool justPressed, bool onMenu, World, int, IssueCommand)` · `string? Hover(Vector2, World, int)`. The first six Draw params are the issue's literal triple, already verbatim in 4 menus (`ManufactureMenu.cs:61`, `DistributionMenu.cs:69`, `StockMenu.cs:26`, `StatisticsMenu.cs:42`); the standard Update is verbatim in 2 (`ManufactureMenu.cs:86`, `DistributionMenu.cs:99`); `Hover(panel, world, player)` matches 4 (`ManufactureMenu.cs:115`, `StockMenu.cs:44`, `StatisticsMenu.cs:108`, `TransportMenu.cs:169`) and the other 3 widen mechanically.
